같은 가상 안건을 끝까지 이어갑니다

가상의 보험회사 영업조직에서 ‘주간회의를 60분에서 30분으로 줄이는 2주 실험’을 제안하는 상황입니다.

  • 원하는 변화: 보고를 읽는 시간을 줄이고 결정할 일에 집중하기.
  • 예상 걱정: 현장 상황을 충분히 공유하지 못할 수 있음.
  • 결정할 것: 실험 여부, 공유할 항목, 돌아볼 기준.
  • 아직 없는 것: 실험 효과를 입증하는 데이터. AI가 숫자를 만들어 채우게 하지 않습니다.

현대해상의 실제 제도나 현안이 아닙니다. 본사 업무를 맡은 분은 가상의 부서 협업회의로 바꿔도 됩니다.

사람이 할 일은 목적과 상황을 설명하고, 결과를 판단하는 것입니다.

먼저 골라보세요

질문 1. 같은 AI인데 왜 사람마다 얻는 답이 다를까요?

A. 어려운 용어를 많이 써야 해서 / B. 목적·상황·판단 기준이 달라서

질문 2. 다음 중 내 회의에 가까운 답을 얻기 쉬운 요청은 무엇일까요?

A. “회의 줄이는 방법 알려줘.”

B. “가상 영업조직의 주간회의가 60분입니다. 30분으로 줄이고 싶지만 현장 정보가 빠질까 걱정됩니다. 2주 실험을 제안하려고 합니다. 예상 반대와 보완책을 함께 정리해주세요.”

함께 확인할 답

두 질문 모두 B입니다. 글자 수보다 필요한 맥락이 있는지가 중요합니다. 첫 요청에서 상황을 충분히 전달하고 이후 대화로 수정해 보세요. 중요한 조건을 빼고 짧은 지시만 반복하는 것은 피합니다.

질문에는 아는 만큼 답하고, 모르겠으면 “아직 정하지 않았어”라고 말합니다. 짧은 답도 모이면 충분한 맥락이 됩니다.

모은 내용을 정리하고 확인하기
정리해줘. 지금까지 내가 말한 내용만 사용하세요.
① 회의 목적 ② 참석자 관점 ③ 바꾸려는 것 ④ 걱정하는 점 ⑤ 결정할 것 ⑥ 아직 모르는 것을 정리하세요.

  • 내가 말하지 않은 이유나 수치가 섞이지 않았습니다.

막히면: “추천하지 말고 질문만 해줘”라고 다시 요청합니다. ‘축적’은 현재 대화에서 재료를 모은다는 뜻이며 다른 채팅이나 Notion에 자동 저장한다는 뜻은 아닙니다.

3. 결과를 먼저 끝까지 읽습니다

요약부터 요청하지 않습니다. 목차를 확인하고 처음부터 끝까지 한 번 읽으며 다음을 표시합니다.

  • 쓸 수 있는 내용: 내 안건을 판단하는 데 도움이 되는 부분.
  • 확인할 내용: 원문·날짜·대상·수치를 다시 볼 부분.
  • 남은 질문: 결과로도 결정할 수 없는 부분.

출처 한 개 이상을 직접 열어 AI 설명과 대조합니다. 수업 중 다 읽지 못하면 남은 범위를 표시해 이어 읽습니다. 끝까지 읽지 않았다면 전체 읽기 완료로 체크하지 않습니다.

슬라이드는 아직 만들지 말고, 먼저 수정할 부분을 물어보세요.

5. 새 대화에서 다시 시험합니다

프로젝트 안에서 새 대화를 열고 “새 회의를 준비하려고 합니다. 먼저 질문해주세요.”라고 말합니다. 역할·말투·질문 순서를 확인합니다. 이전 대화 세부 안건까지 자동으로 정확히 기억한다고 가정하지 말고 필요한 메모를 전달합니다.

  • 지침을 저장하고 다시 열어 확인했습니다.
  • 새 대화에서 원하는 방식으로 질문을 받았습니다.
  • 써본 뒤 지침 한 문장을 고쳤습니다.

막히면: 불편했던 답변 하나를 보여주고 “이 답변을 피하도록 지침을 한 문장만 고쳐줘”라고 요청합니다.

내용을 확인한 뒤 디자인을 고릅니다

슬라이드에 넣을 내용 확정
내가 확인한 회의 준비 메모만 사용해 4장 슬라이드 문안을 정리하세요.
1장: 결정할 질문과 제안 / 2장: 현재 문제와 확인된 근거 / 3장: 예상 우려와 보완책 / 4장: 2주 실험과 돌아볼 기준.

먼저 문안만 보여주고 내가 확인할 때까지 제작하지 마세요.

디자인 5개 중 하나를 선택합니다

번호 스타일 어울리는 회의
1 현대해상 색상 참고형 조직의 익숙한 색감으로 설명
2 비즈니스 미니멀 핵심 결론을 간단히 보고
3 질문 중심 편집형 쟁점을 하나씩 토론
4 비교·판단형 선택지와 판단 기준 비교

아래에서 하나만 복사합니다. 1번은 남색·주황을 이용한 교육용 참고 배색입니다. 공식 CI 색상값·로고가 제공되면 그 원본을 우선하며 로고를 AI로 재현하지 않습니다.

1번 · 현대해상 색상 참고형
확인한 문안에 다음 디자인을 적용하세요. 아직 제작하지 말고 원칙만 기억하세요.
흰 배경, 짙은 남색 제목, 주황색 강조선을 사용하세요.
남색 #003B71, 주황 #F58220은 공식 CI 수치가 아닌 교육용 참고값입니다.
본문은 짙은 회색, 강조색은 핵심 단어와 선에만 쓰세요.
제목은 위쪽, 핵심 내용은 중앙, 판단할 질문은 아래쪽에 두세요. 로고는 생성하지 마세요.
2번 · 비즈니스 미니멀
확인한 문안에 다음 디자인을 적용하세요. 아직 제작하지 말고 원칙만 기억하세요.
흰 배경, 검정 제목, 회색 보조문장과 얇은 구분선만 사용하세요.
한 장에 한 메시지를 담고, 제목과 핵심 문장을 왼쪽 정렬하세요.
넓은 여백을 남기고 장식 아이콘·입체 효과·그림자는 사용하지 마세요.
3번 · 질문 중심 편집형
확인한 문안에 다음 디자인을 적용하세요. 아직 제작하지 말고 원칙만 기억하세요.
아이보리 배경, 짙은 회색 글자, 질문형 제목을 사용하세요.
왼쪽에는 질문과 결론, 오른쪽에는 근거 또는 주의점 한 묶음을 배치하세요.
강조색은 짙은 청록 한 가지로 제한하고 긴 문단은 피하세요.
4번 · 비교·판단형
확인한 문안에 다음 디자인을 적용하세요. 아직 제작하지 말고 원칙만 기억하세요.
흰 배경과 남색 제목, 같은 폭의 2열 비교 구조를 사용하세요.
현재 방식과 제안 방식의 항목 순서를 맞추고 미확인 효과는 가설로 표시하세요.
마지막에는 선택 기준과 남은 질문을 넣으세요. 비교가 필요 없는 장은 한 열로 정리하세요.
5번 · 실행계획형
확인한 문안에 다음 디자인을 적용하세요. 아직 제작하지 말고 원칙만 기억하세요.
흰 배경, 짙은 회색 제목, 차분한 파란 포인트를 사용하세요.
실행계획 장은 준비 → 2주 시험 → 점검의 3단계로 배치하세요.
행동과 확인 기준을 짧게 적고 담당·기한이 미정이면 미정으로 표시하세요.

방법 A · 이미지로 만들기

이미지 생성이 가능할 때 선택합니다. 한 장만 먼저 만들고 글자를 확인합니다.

이미지 슬라이드 제작 요청
확인한 문안과 선택한 스타일로 1번 슬라이드만 16:9 이미지로 만들어주세요.
제목과 핵심 문장을 크게 쓰고 긴 문단과 작은 각주는 피하세요.
가장자리에 충분한 여백을 남기고 한글 문구는 원문 그대로 사용하세요.
이미지 생성 도구가 없으면 만들었다고 하지 말고 알려주세요.
한 장을 확인한 후 다음 장을 요청하겠습니다.

오탈자·숫자·잘린 문장을 확대해 확인합니다. 이미지 글자가 계속 틀리거나 한도에 걸리면 HTML 방식으로 바꿉니다.

방법 B · 단일 HTML로 만들기

CSS를 포함한 단일 HTML 슬라이드
확인한 4장 문안과 선택한 디자인으로 단일 HTML 슬라이드를 만들어주세요.
CSS와 필요한 JavaScript는 HTML 안에 넣고 외부 이미지·폰트·라이브러리는 사용하지 마세요. 여러 파일이나 ZIP은 만들지 마세요.
화면은 16:9 비율이며 좁은 화면에서도 내용이 잘리지 않도록 하세요.
폰트는 'Malgun Gothic', 'Apple SD Gothic Neo', sans-serif 순서로 사용하세요.
제목 40px 이상, 본문 26px 이상을 기본으로 하세요. 내용이 많으면 글자를 줄이기보다 문장을 줄이거나 장을 나누세요.
제목은 위쪽 왼쪽, 내용은 중앙, 쪽수는 오른쪽 아래에 두고 네 가장자리에 5% 이상 안전 여백을 두세요.
이전·다음 버튼과 좌우 방향키 이동을 지원하고 현재 장수를 표시하세요.
인쇄 시 모든 장을 A4 가로로 한 장씩 출력하고 조작 버튼은 숨기세요.
사실·제안·미확인 표시를 유지하고 없는 숫자와 출처를 넣지 마세요.
가능하면 내려받을 수 있는 meeting-slides.html 파일로 제공하세요. 파일 생성이 불가능하면 HTML 코드 전체를 한 블록으로 제공하세요.

저장하고 열기

  1. 파일이 제공되면 내려받아 브라우저로 엽니다.
  2. 코드만 나오면 메모장에 전체 코드를 붙여넣습니다. 다른 이름으로 저장 → 파일 형식 ‘모든 파일’ → meeting-slides.html → UTF-8로 저장합니다.
  3. 파일 이름이 .html.txt가 아닌지 확인합니다. 어렵다면 강사와 함께 확인합니다.
  4. 파일을 열고 마지막 장까지 이동합니다. 내용 확인 후 전달할 때는 HTML 파일 하나를 사용합니다.
  • 한글·숫자·근거가 원문과 같습니다.
  • 글자와 도형이 겹치거나 잘리지 않습니다.
  • 제안과 사실이 구분됩니다.
  • 마지막 장에 결정할 질문이 있습니다.

막히면: 잘리는 장과 위치를 구체적으로 말합니다. “3번 장 아래가 잘립니다. 제목·본문 글자 크기는 유지하고 본문을 170자 이내로 줄여주세요. 카드 여백을 조정하고 그래도 넘치면 장을 나눠주세요. 전체 단일 HTML을 다시 제공해주세요”라고 요청한 뒤 모든 장을 다시 확인합니다.
